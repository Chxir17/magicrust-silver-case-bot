# Magic Rust — бот бесплатного кейса

Автоматически открывает кейс «Бесплатное серебро» на [magicrust.gg](https://magicrust.gg/ru)
раз в 10 часов и присылает результат в Telegram.

Работает через настоящий браузер (Playwright + Chromium) и нажимает те же кнопки, что и
человек. Вход в Steam выполняется вручную один раз — пароль в скрипте не хранится и
никуда не передаётся, сохраняется только cookie-сессия сайта.

Игроков может быть сколько угодно: у каждого свой профиль браузера, своё расписание и
свои уведомления. Доступ выдаёт администратор — тот chat id, что указан в `.env`.

## Как это работает

| Шаг | Действие |
|-----|----------|
| 1 | Chromium открывает `magicrust.gg/ru` с сохранённым профилем |
| 2 | Магазин переключается на нужный режим игры |
| 3 | Открывается карточка «Бесплатное серебро» |
| 4 | Нажимается кнопка «Открыть кейс» |
| 5 | Ответ `/product-buy` разбирается, результат пишется в лог и Telegram |
| 6 | Следующая попытка планируется через 10 часов 8 минут |

Таймер systemd запускает бота каждые 20 минут. Бот сверяется с собственным расписанием
и открывает браузер только когда перезарядка действительно закончилась. Благодаря этому
кейс забирается почти сразу после её окончания, даже если сервер перезагружался.

### Ответы сайта

| Ответ `/product-buy` | Значение |
|----------------------|----------|
| `{"success": true, ...}` | кейс открыт, серебро начислено |
| `{"success": false, "message": "Товар доступен каждые 10 часов"}` | перезарядка не закончилась |

Оба ответа приходят с кодом HTTP 200, поэтому результат определяется полем `success`.
Оставшееся время перезарядки сайт не сообщает — бот считает его сам от последнего
успешного открытия.

## Структура проекта

```
bot.py                точка входа, указана в юнитах systemd
mrbot/
  config.py           пути, селекторы сайта, настройки окружения
  fmt.py              форматирование времени и чисел
  users.py            реестр игроков, права, каталоги аккаунтов
  state.py            состояние: история, счётчики, расписание
  browser.py          Chromium и страница magicrust.gg
  case.py             открытие кейса и разбор ответа
  cookies.py          приведение куки к формату Playwright
  telegram.py         уведомления и команды бота
  admin.py            выполнение команд, пришедших из Telegram
  texts.py            все тексты для человека — их правят здесь
  cli.py              разбор аргументов командной строки
tools/
  get-cookies.py      его бот отдаёт игрокам по /cookies: выгружает куки у них
scripts/
  dev-setup.sh        подготовка окружения на своей машине
  install.sh          установка на сервер
  update.sh           обновление из репозитория
  mr                  обёртка для запуска команд
  magicrust-admin     root-помощник для /restart и /update
  enable-remote-admin.sh  выдача прав этому помощнику
systemd/              юниты таймера и Telegram-сервиса
state/                реестр, профили браузера, логи (в git не попадает)
  users.json          кто допущен к боту и кто ждёт одобрения
  users/<chat_id>/    профиль Chromium и состояние одного игрока
  bot.log             общий журнал
```

Селекторы сайта собраны в `mrbot/config.py`. При изменении вёрстки magicrust.gg
править нужно только их.

Все формулировки, которые видит человек, лежат в `mrbot/texts.py`, по коду их нет:

| Класс | Что содержит |
|-------|--------------|
| `Chat` | ответы бота в Telegram |
| `Cli` | вывод команд в терминале |
| `Menu` | подписи команд в подсказке Telegram |
| `Words` | формы слов для склонения по числу |
| `Time` | формат даты и промежутков времени |

Подстановки записаны фигурными скобками с именами — `{silver}`, `{when}`. Менять
текст вокруг них можно свободно, сами имена трогать нельзя.

## Установка на своей машине

Нужна для входа в Steam: на сервере нет графической оболочки, а Steam Guard требует
ручного ввода кода.

Требуется Python 3.10–3.13. Скрипт находит подходящую версию, создаёт виртуальное
окружение, ставит зависимости и Chromium, готовит `.env`:

```bash
./scripts/dev-setup.sh
```

Вход в Steam:

```bash
./scripts/mr login
```

Откроется окно браузера. Нажмите «Войти» → «Войти через Steam» и введите свои данные.
Закройте плашку про cookie кнопкой «Ok» — профиль запомнит это, и она перестанет
перекрывать страницу при автоматических запусках. Когда сайт покажет ваш профиль,
окно закроется само.

Проверка:

```bash
./scripts/mr status
```

Разовый запуск, открывает кейс сразу, если он доступен:

```bash
./scripts/mr run --force
```

## Установка на сервер

Подойдёт Debian или Ubuntu с 1 ГБ оперативной памяти.

```bash
git clone https://github.com/Chxir17/magicrust-silver-case-bot.git /tmp/mr-install
sudo /tmp/mr-install/scripts/install.sh https://github.com/Chxir17/magicrust-silver-case-bot.git
```

Скрипт выполняет:

1. установку `python3-venv` и `git`;
2. создание системного пользователя `magicrust` с домашним каталогом `/opt/magicrust-bot`;
3. подключение репозитория и выкладку кода;
4. создание виртуального окружения, установку зависимостей и Chromium;
5. создание `.env` из примера с правами `600` и значением `HEADLESS=1`;
6. установку юнитов systemd и включение таймера;
7. копирование обёртки `mr` в `/usr/local/bin`.

Скрипт можно запускать повторно: `.env`, каталог `state/` и сессия сайта не затрагиваются.

После установки удалите временную копию и заполните токен Telegram:

```bash
rm -rf /tmp/mr-install
sudo nano /opt/magicrust-bot/.env
```

## Перенос сессии

Вход в Steam выполняется на своей машине, на сервер переносятся только cookie.

На своей машине:

```bash
./scripts/mr export-cookies state/cookies.json
scp state/cookies.json <сервер>:/tmp/cookies.json
```

На сервере:

```bash
sudo install -o magicrust -g magicrust -m 600 /tmp/cookies.json /opt/magicrust-bot/state/cookies.json
mr import-cookies /opt/magicrust-bot/state/cookies.json
mr status
```

`mr status` должен показать активную сессию. После переноса удалите файл — это ключ
доступа к аккаунту на сайте:

```bash
sudo shred -u /opt/magicrust-bot/state/cookies.json /tmp/cookies.json
```

При переносе cookie плашка про cookie на сайте остаётся непринятой и перекрывает низ
страницы. Установите `MR_ACCEPT_COOKIE=1` в `.env`, чтобы бот закрывал её сам.

Тот же файл можно отправить боту в Telegram — см. [Перенос сессии через чат](#перенос-сессии-через-чат).

### Если сессия не принимается

Сайт может привязывать сессию к адресу. В этом случае войдите в Steam прямо на сервере
через графический браузер по VNC:

```bash
sudo apt install -y xvfb x11vnc
Xvfb :99 -screen 0 1440x900x24 &
x11vnc -display :99 -localhost -nopw -forever &
```

С локальной машины пробросьте порт (`ssh -L 5900:localhost:5900 <сервер>`), подключитесь
VNC-клиентом к `localhost:5900` и выполните на сервере:

```bash
sudo -u magicrust -H env DISPLAY=:99 HEADLESS=0 /opt/magicrust-bot/venv/bin/python /opt/magicrust-bot/bot.py login
```

## Обновление

На своей машине:

```bash
git status --short
git add -A && git commit -m "описание изменений" && git push origin master
```

`.env` и `state/` перечислены в `.gitignore`, токен и сессия в репозиторий не попадают.

На сервере:

```bash
sudo mr update
```

Скрипт сравнивает старую и новую ревизии и выполняет только необходимое:
переустанавливает зависимости при изменении `requirements.txt`, обновляет юниты при
изменении каталога `systemd/`, перезапускает Telegram-сервис. Если новых коммитов нет,
сообщает об этом и завершается.

Сервис `magicrust-case` перезапускать не требуется: он завершается после каждого
запуска и берёт новый код при следующем срабатывании таймера.

## Telegram

Создайте бота у [@BotFather](https://t.me/BotFather), узнайте свой chat id у
[@userinfobot](https://t.me/userinfobot) и заполните `.env`:

```
TG_TOKEN=123456:AA...
TG_CHAT_ID=123456789
```

`TG_CHAT_ID` — администратор бота. Он выдаёт доступ остальным, и только ему доступны
команды, управляющие сервером. Администраторов может быть несколько — через запятую.

После этого приходят уведомления об открытых кейсах и об истечении сессии.

### Ответы на команды

Уведомления работают без дополнительных настроек. Чтобы бот отвечал на команды, нужен
постоянный опрос Telegram — отдельный сервис:

```bash
sudo systemctl enable --now magicrust-telegram.service
```

Команды делятся на быстрые (читают состояние) и медленные (запускают браузер,
`systemctl` или `git`). На медленные бот сначала присылает подтверждение, затем
результат с кодом возврата.

Каждая команда работает с аккаунтом того, кто её прислал: `/status` показывает его
расписание, `/run` открывает кейс на его аккаунте.

| Команда | Ответ | Кому |
|---------|-------|------|
| `/start`, `/help` | список доступных команд | всем допущенным |
| `/status` | время следующей попытки, счётчики | всем допущенным |
| `/last` | что выпало в последний раз | всем допущенным |
| `/stats` | история открытий, среднее, лучшее и худшее значения | всем допущенным |
| `/run` | попытка открыть кейс с учётом расписания | всем допущенным |
| `/run force` | то же, игнорируя расписание | всем допущенным |
| `/check` | полная проверка сессии через браузер | всем допущенным |
| `/paste` | принимает ключ сессии, скопированный из браузера | всем допущенным |
| `/cookies` | присылает файлом программу для выгрузки куки | всем допущенным |
| `/login` | как перенести сессию Steam | всем допущенным |
| `/users` | игроки, их состояние и заявки на доступ | администратору |
| `/approve id` | выдать доступ | администратору |
| `/remove id` | закрыть доступ и стереть сессию игрока | администратору |
| `/log [N]` | последние строки журнала | администратору |
| `/timer` | расписание таймера | администратору |
| `/restart` | обновить юниты и перезапустить | администратору |
| `/update` | обновить код из репозитория | администратору |
| `/version` | версия кода и список команд | администратору |

Журнал общий на всех, поэтому `/log` закрыт: в нём видны чужие ники и результаты.
Попытка игрока выполнить админскую команду отклоняется и попадает в журнал.

При запуске сервис публикует список команд через `setMyCommands`, поэтому при вводе
`/` в чате Telegram показывает подсказку с описаниями. Меню задаётся отдельно каждому
чату: администратор видит полный набор, игрок — только свои команды, посторонний,
наткнувшийся на бота в поиске, — ничего.

Проверить без запуска сервиса: отправьте боту `/start`, затем выполните

```bash
mr telegram --once
```

Одновременный запуск исключён: попытки из чата, обход очереди по таймеру и импорт
куки защищены общей блокировкой — Chromium на сервере всегда один.

### Перенос сессии через чат

Есть два пути: вставить ключ сессии сообщением или прислать файл с куками. Оба
кончаются одинаково — бот подключает сессию в профиль игрока и убирает секрет из
чата: сообщение с ключом и присланный файл удаляются через `deleteMessage`, а
временный файл на сервере стирается сразу после импорта.

#### Ключ сессии сообщением — `/paste`

Ничего скачивать и устанавливать не нужно. Человек открывает magicrust.gg, где уже
вошёл через Steam, жмёт F12 → Application → Cookies, копирует значение
`magicrust_session` и присылает его в чат. Бот принимает вставку в любом виде:

- голое значение (`eyJpdiI6…`);
- `magicrust_session=eyJpdiI6…`;
- несколько кук через `;` или с новой строки;
- целый JSON, скопированный текстом.

Отдельная команда не обязательна: длинная строка без пробелов распознаётся как ключ
сама. `/paste` без аргумента присылает пошаговую инструкцию.

Почему нельзя обойтись строчкой в консоли браузера: `magicrust_session` помечен
флагом `HttpOnly`, поэтому ни `document.cookie`, ни закладка-букмарклет его не видят
— это защита самого браузера. Панель разработчика показывает такие куки, а скрипты
страницы нет. По той же причине нет и способа «войти прямо в боте»: сессию создаёт
Steam в браузере того, кто входит. Логин и пароль Steam боту передавать не нужно —
и не следует, даже если он попросит.

На телефоне панели разработчика нет, там подойдёт `/cookies`.

#### Файлом

Где взять файл, если репозитория под рукой нет: команда `/cookies` присылает
`tools/get-cookies.py` прямо в чат. Человек запускает его у себя:

```bash
python3 get-cookies.py
```

Скрипт спрашивает, каким путём достать куки:

1. **Вход через Steam** — открывает окно браузера, человек входит как обычно, скрипт
   дожидается возврата на magicrust.gg и сохраняет куки. Нужен Playwright с Chromium,
   скрипт предлагает поставить их сам.
2. **Из Firefox** — читает `cookies.sqlite` профиля, если человек уже вошёл на сайт в
   этом браузере. Достаточно голого Python, ничего ставить не нужно.

Рядом со скриптом появляется `cookies.json`, его и отправляют боту. Пароль Steam
скрипт не видит: сохраняются только куки сайта.

Подходит и выгрузка из расширения вроде Cookie-Editor: бот сам отбирает куки
magicrust.gg и приводит `expirationDate` и `sameSite` к формату Playwright. Файл без
куки нужного сайта отклоняется сразу, без запуска браузера.

Куки Chrome лежат зашифрованными, поэтому читать его профиль скрипт не умеет — для
Chrome подойдут `/paste`, вход через Steam или расширение.

Файл содержит ключ доступа к аккаунту на сайте и проходит через серверы Telegram.
Если это нежелательно, переносите его через `scp`, как описано выше.

Войти в Steam прямо из Telegram нельзя: браузер внутри чата не запускается, а вход
в мобильном браузере создаёт сессию на телефоне, а не на сервере.

### Команды /restart и /update

Им нужны права root, которых у сервиса нет. По умолчанию бот отвечает, что помощник
не установлен, — остальные команды при этом работают. Чтобы включить:

```bash
sudo /opt/magicrust-bot/scripts/enable-remote-admin.sh
```

Скрипт ставит root-помощник `/usr/local/sbin/magicrust-admin` и правило sudo ровно
на два его действия. Помощник принадлежит root, подменить его из-под `magicrust`
нельзя.

При этом `restart` копирует юниты из `/opt/magicrust-bot`, доступного на запись
пользователю `magicrust`. Тот, кто получит доступ к боту, сможет через это поднять
права до root. На выделенной машине под один бот это приемлемо; иначе не включайте
и перезапускайте вручную.

Отключить:

```bash
sudo rm /etc/sudoers.d/magicrust /usr/local/sbin/magicrust-admin
```

## Игроки и доступ

Бот обслуживает несколько человек сразу. У каждого свой каталог
`state/users/<chat_id>/`: профиль Chromium с его сессией, его история и его
расписание. Чужое состояние не видно и не пересекается.

Как человек попадает в бот:

1. Пишет боту `/start`. В ответ получает отказ и свой chat id, администратору
   уходит заявка. Повторные сообщения администратора уже не беспокоят.
2. Администратор смотрит `/users` и выполняет `/approve 123456789`.
3. Новичку приходят подтверждение и инструкция. Проще всего `/paste` — скопировать
   ключ сессии из браузера, не устанавливая ничего; есть и `/cookies` с готовой
   программой. Репозиторий новичку не нужен ни в том, ни в другом случае.
4. Он присылает ключ или файл — бот подключает сессию и дальше открывает кейс сам.

Администратор может добавить человека и заранее, не дожидаясь заявки: `/approve` с
любым chat id. Узнать чужой id можно у [@userinfobot](https://t.me/userinfobot).

`/users` показывает всех разом:

```
Игроки (3):
  Илья · 123456789 · админ — следующая попытка через 4 ч 12 мин · открыто 37
  Вася @vasya · 222222222 — готов к попытке · открыто 5
  Петя · 333333333 — сессия не передана

Заявки (1):
  Костя @kostya · 444444444 — /approve 444444444
```

`/remove id` закрывает доступ и удаляет каталог игрока вместе с сессией — на сервере
не остаётся ключей от чужого аккаунта. Администратора из `.env` удалить нельзя.

Таймер обходит игроков по очереди, по одному Chromium за раз: у кого срок подошёл —
тому попытка, остальные пропускаются. Сбой у одного не останавливает остальных, ему
просто назначается повтор. Профиль браузера занимает 50–150 МБ на человека — это
основной расход места при большом числе игроков.

## Команды

Обёртка `mr` подставляет виртуальное окружение и, на сервере, пользователя `magicrust`.
На своей машине она доступна как `./scripts/mr`, на сервере — как `mr`.

| Команда | Назначение |
|---------|------------|
| `mr login` | вход через Steam |
| `mr status` | состояние сессии и расписания |
| `mr run` | обойти очередь игроков, у кого подошёл срок |
| `mr run --force` | то же, игнорируя расписание |
| `mr run --user ID` | попытка только для одного игрока |
| `mr export-cookies FILE` | выгрузить сессию |
| `mr import-cookies FILE` | загрузить сессию |

Команды `login`, `status`, `run`, `export-cookies` и `import-cookies` принимают
`--user ID` и работают с аккаунтом этого игрока. Без флага берётся аккаунт
администратора — первый chat id из `TG_CHAT_ID`.
| `mr telegram --once` | обработать накопившиеся команды |
| `mr logs [N]` | последние строки журнала |
| `mr timer` | расписание таймера |
| `mr restart` | обновить юниты и перезапустить |
| `sudo mr update` | обновить код из репозитория |

Без обёртки:

```bash
sudo -u magicrust -H /opt/magicrust-bot/venv/bin/python /opt/magicrust-bot/bot.py status
```

## Настройки

Файл `.env` в корне проекта.

| Переменная | По умолчанию | Назначение |
|------------|--------------|------------|
| `TG_TOKEN` | — | токен бота от @BotFather |
| `TG_CHAT_ID` | — | chat id администратора; несколько — через запятую |
| `HEADLESS` | `1` | `0` показывает окно браузера, нужно для входа в Steam |
| `MR_GMOD` | `modded` | режим игры: `modded` или `vanillax2plus` |
| `MR_TZ` | `Europe/Moscow` | часовой пояс для отображения времени |
| `MR_TIMEOUT_SCALE` | `1` | множитель таймаутов для медленных серверов |
| `MR_ACCEPT_COOKIE` | `0`, в `.env.example` — `1` | `1` разрешает боту закрыть плашку про cookie |
| `MR_UA` | — | переопределение User-Agent |

Файлы состояния в каталоге `state/`:

| Файл | Содержимое |
|------|------------|
| `users.json` | реестр доступа и заявки |
| `bot.log` | журнал работы, общий на всех |
| `users/<id>/state.json` | история открытий, счётчики, расписание игрока |
| `users/<id>/profile/` | профиль Chromium с сессией сайта |
| `users/<id>/last_open.png` | скриншот последней попытки |

Состояние прежней однопользовательской версии (`state/state.json` и `state/profile`)
переезжает в каталог администратора при первом запуске — вручную ничего переносить
не нужно.

## Решение проблем

| Сообщение | Причина и решение |
|-----------|-------------------|
| `сессия истекла` | выполните `mr login` заново или перенесите cookie |
| `кейс не виден в режиме ...` | укажите `MR_GMOD=vanillax2plus` |
| `клик по ... перекрыт` | установите `MR_ACCEPT_COOKIE=1` |
| `ответ от /product-buy не пришёл` | сервер перегружен, увеличьте `MR_TIMEOUT_SCALE` до 3 |
| `кнопка «Открыть кейс» не найдена` | изменилась вёрстка сайта, проверьте `state/users/<id>/last_error.png` и селекторы в `config.py` |
| `нет куки magicrust.gg` | выгружены куки не того сайта — нужен именно magicrust.gg |
| `нет куки magicrust_session` | скопировано значение не той строки, см. `/paste` |
| `Куки загружены, но сессия гостевая` | ключ устарел или скопирован не полностью — повторите вход на сайте и скопируйте заново |
| `Команда доступна только администратору` | команда управляет сервером; её выполняет владелец бота |
| Chromium не запускается | выполните `sudo playwright install-deps chromium`, проверьте `HEADLESS=1` |
| `Trigger: n/a` у таймера | обновите юнит и выполните `mr restart` |
| `Permission denied` при `cd /opt/magicrust-bot` | каталог принадлежит пользователю `magicrust`; используйте `mr` или полные пути |
| `kex_exchange_identification` | SSH использует нестандартный порт, подключайтесь по имени из `~/.ssh/config` |

Подробности любой попытки — в журнале:

```bash
mr logs 50
```

## Ограничения

С каждого аккаунта забирается один бесплатный кейс раз в 10 часов — на большее сайт
не даёт. Игроков может быть много, но обслуживаются они по очереди, одним Chromium:
на слабом VPS каждая попытка занимает десятки секунд, и при нескольких десятках
игроков очередь перестанет укладываться в интервал таймера.

Доступ к боту означает доступ к сессии сайта: тот, у кого есть права администратора
сервера, может прочитать куки любого игрока из `state/users/`. Пускать в бот стоит
тех, кто на это согласен.
